# ANGLE性能修正记录

保留Windows ANGLE/Direct3D11以避免本机AMD原生OpenGL花屏，不降低分辨率、不调整物理120Hz、角色速度或攻击频率。

首页原GameHandoff通过PackedScene导出引用整套正式关卡，导致还没按开始就加载其全部依赖。现导出场景路径，只有按开始才发起后台资源预载，利用原有下降/加载动画准备，到原交接点仍由prepare实例化与同一相机接管。直接调用prepare的测试或入口继续同步加载；不新加过场。

回顾记录原每秒8次从1920×1080视口读回，再在CPU缩为640×360并压JPEG。现在按同样频率单次更新640×360 SubViewport，以GPU先缩小画面，再读回JPEG；仍采集真实屏幕，保留最近6秒、首次失败、四关死亡计数及快照。

## 本机短时测量

1280×720窗口、逻辑1920×1080、AMD Radeon 780M ANGLE，4秒测量段，受其他程序/内存变化影响，非全关卡长期基准。

- 首页贴图视频内存：原2113 MB，修改后346～348 MB，约减少84%。
- 首轮关卡录制段：原约74 FPS / p95 34.36 ms / 最大197.2 ms；修改后约119 FPS / p95 15.20 ms / 最大28.68 ms。不能将全部差异归因于单项修改，后台资源压力也变化。
- 更严格的同进程旧录制/新录制对照：旧107 FPS / p95 24.94 ms；新111 FPS / p95 16.14 ms，真实帧数43。新段最大73 ms仍有系统级偶发停顿，未声称所有长帧完全消失。
- 编辑器实际工作集在重新载入资源后由约2712 MB降至753 MB。

retrospective_capture原生测试验证：真实屏幕从红到绿正确变化、JPEG为640×360、持续采集、死亡保留首段、冻结停止采集，全部通过。settlement_descent统计/容量/回放检查通过；main_menu_camera_handoff无窗口正常开始与相机交接通过。原生main_menu_camera_handoff曾触发其人为位移后的存活断言（其余相机断言通过），因此不将它报告为原生全通过。
